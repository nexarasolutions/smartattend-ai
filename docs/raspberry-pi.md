# Raspberry Pi Integration

## Scope

The edge client is a sensor-neutral transport and persistence module, not a finished sensor driver. RFID, QR, fingerprint and camera are possible future adapter types. No sensor model, camera pipeline, wiring diagram or detection rule is assumed. A future adapter should normalize a confirmed physical observation into an event and call `DeviceClient.submit_attendance`; it must not decide account permissions or bypass the server's session/classroom checks.

The Pi communicates only with the Manus-hosted Flask API over HTTPS. Routes are relative to the published HTTPS application origin plus `/api`:

- `POST /api/device/register`
- `POST /api/device/heartbeat`
- `POST /api/device/attendance`
- `GET /api/device/status`
- Admin APIs: `GET /api/admin/devices`, activation, credential rotation and device maintenance.

See [`openapi.yaml`](openapi.yaml) for transport headers and schemas.

## Install on a Raspberry Pi

Copy the `iot/` package to a supported Python 3 device (Python 3.10+ recommended) and install the minimal edge dependency:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r iot/requirements.txt
export SMARTATTEND_API_URL="https://<published-smartattend-origin>"
export SMARTATTEND_DEVICE_ID="science-block-pi-01"
```

Use the published HTTPS application origin for real devices. Do not turn off TLS verification. HTTP is rejected unless a test explicitly uses loopback and enables the local-only override.

## Enroll and activate

1. A SmartAttend Admin creates a classroom-scoped, expiring one-time enrollment token from Device Management. The classroom is chosen in the Admin UI; the Pi cannot select a different classroom in its register body.
2. On the Pi, run:

   ```bash
   .venv/bin/python -m iot.cli enroll --firmware-version 1.0.0
   ```

   The token is entered through a hidden terminal prompt, not a command-line argument or shell history. The API redeems it once and returns a new, device-specific credential once. The CLI writes it to the protected local credentials file and omits its value from the result/log.
3. The device appears pending. An Admin reviews the physical device ID and mapped classroom, then activates it. Pending/revoked devices cannot submit authenticated events.
4. Protect the device's service account and filesystem. The credentials directory is mode `0700`; the credential file and local event queue are mode `0600`. Back up credentials only through the organization's approved secret-handling process.

Enrollment tokens are randomly generated by the server, stored as hashes, classroom-scoped and expire after 1–60 minutes. A device credential is independently random, stored server-side as a verifier, and can be revoked/rotated by an Admin.

## Heartbeat and operations

The server marks a device offline when its latest heartbeat is older than `SMARTATTEND_HEARTBEAT_OFFLINE_SECONDS` (default five minutes). A one-minute loop is the recommended starting cadence:

```bash
.venv/bin/python -m iot.cli heartbeat
.venv/bin/python -m iot.cli heartbeat-loop --interval-seconds 60
.venv/bin/python -m iot.cli status
.venv/bin/python -m iot.cli queue-status
.venv/bin/python -m iot.cli retry --limit 100
```

The heartbeat sends a unique event ID, a timezone-aware ISO-8601 `timestamp`, firmware version and an allow-listed device-health summary. No user identity or attendance observation is included in a heartbeat.

A deployment can run the heartbeat loop under its process supervisor (for example, systemd). Keep `SMARTATTEND_API_URL` and `SMARTATTEND_DEVICE_ID` in a root-owned environment file (mode `0600`); keep the device credential in the app-managed protected state directory. Do not place enrollment tokens or bearer credentials in logs or process arguments.

## Attendance events and offline retry

A sensor adapter can submit a valid observation:

```bash
.venv/bin/python -m iot.cli submit \
  --session-id <server-issued-class-session-uuid> \
  --roll-number <observed-roll-number> \
  --status Present \
  --sensor-type unspecified
```

Production integrations should call the Python method with a timezone-aware observation time and a sensor-generated reference that contains no unnecessary personal data. The client creates an `event_id` and `idempotency_key` before transmission. On network failure or `429`/`5xx`, it stores the same event locally and retries with exponential backoff; the server recognizes duplicate event IDs/keys and duplicate session/student records. Events that fail validation are terminally logged with a safe error code rather than silently changing a record. Server acknowledgments are `accepted`, `duplicate` or a structured rejection.

The server checks that the device is active, the class session exists/is eligible, the student is active and belongs to the section, the device is mapped to the session's classroom, timestamps carry a timezone and fall within the allowed window, and no attendance record already exists for that student/session. API authorization cannot be replaced by an edge-side decision.

## Pluggable sensor adapter

`iot/sensors.py` defines the adapter boundary. Implement only after the actual sensor/model and consent/privacy requirements are confirmed. The adapter should provide a normalized event with a valid existing session, roll number or approved student reference, status, timezone-aware timestamp and sensor type. It should not store face images, fingerprint templates or raw QR content in the queue. Current server audit/event records keep the sensor category and safe status but do not require raw biometric/image payloads.

## Troubleshooting

- `HTTPS_REQUIRED`: use the published HTTPS origin; do not use a redirecting HTTP URL.
- `ENROLLMENT_TOKEN_EXPIRED`/`ENROLLMENT_TOKEN_INVALID`: ask an Admin to issue a new classroom-scoped token; do not reuse a redeemed token.
- `DEVICE_AUTH_INVALID`: have an Admin verify device activation and rotate/re-enroll the credential after revocation.
- `DEVICE_OFFLINE`: check network, system clock/NTP and heartbeat schedule; time-zone-aware timestamps are mandatory.
- `queue-status`: inspect pending and terminal counts locally without printing student/event payloads. Fix a terminal cause before manually re-submitting; preserve the original event identity when retrying transient failures.
